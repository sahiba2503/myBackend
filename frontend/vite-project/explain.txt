I will explain the flow of my Add Task page.

First, the user enters the task title and description.

For the title input, I use `value={title}` and `onChange`.

When the user types something, the `onChange` event runs and `setTitle()` updates the title state.

Similarly, `setDescription()` stores the description in the description state.

Then the user clicks the Save Task button.

The `onClick` calls my `handleAddTask` function.

Inside this function, I first use `event.preventDefault()` to stop the browser's default form submission.

Then I validate the user input.

If the title or description is empty, I show an error message using `setError()` and stop the function using `return`.

Then I check whether the title and description contain at least 3 characters.

If the validation is successful, I create a `payload` object containing the task name and description.

After that, I check the `id`.

If the `id` exists, it means the user is editing an existing task.

So I send a PATCH request to my backend using the task ID.

If the `id` does not exist, it means the user is adding a new task.

So I send a POST request to the `/add-todo` endpoint.

I use `JSON.stringify()` to convert my JavaScript object into JSON before sending it to the backend.

Then I receive the response from the backend and use `res.json()` to convert the response into JavaScript data.

If `data.success` is true, I navigate the user back to the Todo Task page.

If there is an error, I show the error message using `setError()`.

I also use `catch()` to handle network or API errors.

Finally, I use `finally()` to set loading to false after the request is completed.

So the complete flow is:

User enters data → state stores data → user clicks Save → validation → check ID → POST for new task or PATCH for editing → backend response → success or error → navigate to Todo Task page.
